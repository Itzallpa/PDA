ผังและขั้นตอนการทำงานของระบบ (System Workflow)

📤 1. ขั้นตอนการเบิกเครื่อง PDA (Check-Out Process) สถานะหลังเบิก: เบิกใช้งาน 🔴
1 เลือกโหมดเบิกออก พนักงานไปที่หน้าจอประจำตู้แผนกตนเอง กดเลือกโหมด "เบิกออก"
→
2 ยิงรหัสพนักงาน ยิงบาร์โค้ดบัตรพนักงาน (Staff ID) เพื่อระบุตัวตนผู้ถือครองเครื่อง
→
3 ยิงรหัส PDA ยิง Barcode หรือ QR Code ของเครื่อง (รองรับทั้ง Original SN หรือ Custom Code)
→
✓ ตรวจสอบ & บันทึกสำเร็จ ระบบตรวจสอบสังกัดตู้ บันทึก Log เวลาเบิก ส่งเสียง Chime และเปลี่ยนเป็นสีแดง
📥 2. ขั้นตอนการคืนเครื่องเข้าตู้ (Check-In Process) สถานะหลังคืน: ในตู้พร้อมใช้ 🟢
1 เลือกโหมดคืนตู้ กดปุ่ม "คืนเข้าตู้" ที่หน้าจอประจำตู้
→
2 ยิงบาร์โค้ด PDA ยิงรหัสตัวเครื่องแล้วเสียบเข้าช่องชาร์จ (ไม่ต้องสแกนบัตรพนักงาน)
→
3 ตรวจตู้สังกัด ระบบตรวจว่าเครื่องตรงกับตู้ประจำแผนกนี้หรือไม่เพื่อความปลอดภัย
→
✓ คืนสำเร็จเข้าตู้ เคลียร์ชื่อผู้ถือครอง อัปเดตไฟสีเขียว บันทึกประวัติเวลาคืน และส่งเสียง Chime
🛡️ 3. ระบบป้องกันการยิงข้ามตู้ (Department Isolation Guard) ระบบความปลอดภัย

เพื่อป้องกันอุปกรณ์สูญหายหรือย้ายแผนกโดยไม่ได้รับอนุญาต หากมีการนำ PDA สังกัดตู้แผนกหนึ่ง (เช่น IB) ไปยิงทำรายการที่ตู้ของแผนกอื่น (เช่น OBS):

✕ ปฏิเสธทันที (REJECT) ระบบจะไม่อนุญาตให้ทำรายการ และไม่เปลี่ยนสถานะเครื่อง
→
🔊 เสียงเตือน Siren ส่งเสียงสัญญาณเตือนภัย Buzzer เสียงดังเพื่อแจ้งให้พนักงานทราบ
→
⚠️ แจ้งตู้ที่ถูกต้อง แสดงข้อความสีแดงเตือนชัดเจนระบุว่าเครื่องสังกัดตู้แผนกใด ให้นำกลับไปยิงที่ตู้เดิม
🚨 4. ระบบตรวจจับและติดตามอุปกรณ์ค้างเกิน 3 วัน (Overdue 3-Day Alert) เกณฑ์ > 72 ชั่วโมง
1 คำนวณอัตโนมัติ ระบบประมวลผลเครื่องที่ถูกเบิก (CHECKED_OUT) นานเกิน 3 วัน (72 ชม.) ตลอดเวลา
→
2 แสดงเตือนบน Dashboard ขึ้นกล่องเตือนสีแดงเด่นด้านบนสุด ระบุ SN, แผนก, พนักงาน และจำนวนวันที่ค้าง
→
3 ติดตาม & ปิดสถานะ หัวหน้างานติดตามเครื่อง หรือกด "บันทึกคืนตู้ทันที" ได้โดยตรงจากหน้าจอ
☁️ 5. สถาปัตยกรรมข้อมูลและการซิงค์คลาวด์ (Cloud Sync Architecture) Turso Cloud + Local SQLite
⚡ Local SQLite Engine บันทึกลง data/pda_storage.db ในเครื่องแม่ทันที ตอบสนองไวแม้ไม่มีเน็ต
⇄
☁️ Turso Cloud Database ซิงค์สองทางอัตโนมัติผ่าน LibSQL Cloud ข้อมูลไม่หายและเชื่อมโยงข้ามเครื่องแบบ Real-Time
